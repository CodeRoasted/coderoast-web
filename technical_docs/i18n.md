# Internationalisation (i18n)

## How It Works

All copy lives in a single file: `src/i18n/translations.ts`.

```
translations
├── en   { nav, hero, portfolio, comingSoon, donation, licensing, footer }
└── fr   { nav, hero, portfolio, comingSoon, donation, licensing, footer }
```

The active language is stored in Zustand (`useStore → language`).  
The `useTranslation()` hook returns `translations[language]` — a fully typed object that mirrors the `en` shape.

## Using Translations in a Component

```tsx
import { useTranslation } from '@/hooks/useTranslation'

export default function MyComponent() {
  const t = useTranslation()
  return <h1>{t.hero.tagline}</h1>
}
```

TypeScript will error if you access a key that does not exist in both locales.

## Switching Language

```tsx
import { useStore } from '@/store/useStore'

const { setLanguage } = useStore()
setLanguage('fr')   // or 'en'
```

`LanguageToggle.tsx` calls this on click. No page reload needed.

## Adding a New Language

1. Add a new locale key to `translations` in `src/i18n/translations.ts`, copying the full `en` structure.
2. Extend the `Language` union in `src/store/useStore.ts`:
   ```ts
   type Language = 'en' | 'fr' | 'de'
   ```
3. Update `LanguageToggle.tsx` to cycle through the new language.

## Adding New Translation Keys

1. Add the key under **both** `en` and `fr` in `translations.ts`.
2. The `TranslationKey` type is automatically derived — TypeScript will surface missing keys in the other locale at build time.
